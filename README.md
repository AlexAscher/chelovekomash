# Интернет-магазин

Учебный интернет-магазин с веб-интерфейсом для покупателей и менеджеров, REST API и уведомлениями о новых заказах в реальном времени.

## Возможности

- Каталог товаров с описаниями, ценами, категориями, брендами и фотографиями.
- Поиск по названию и описанию товара.
- Регистрация покупателей и вход по JWT-токену с автоматическим обновлением access-токена.
- Оформление заказа с одним или несколькими товарами, сохранением цены на момент покупки и расчётом суммы.
- Просмотр и отмена собственных заказов; администратор может просматривать все заказы.
- Разделы управления товарами, категориями и брендами для менеджеров и администраторов.
- Управление пользователями и их ролями для администратора.
- WebSocket-уведомления о новых заказах для менеджерской группы.
- Django Admin для работы с данными и заказами.
- Автоматически формируемая документация REST API в Swagger UI.

## Технологии

- **Backend:** Python, Django 6, Django REST Framework, Simple JWT, Django Channels, Daphne, SQLite.
- **Frontend:** Vue 3, Vue Router, Vuetify, Axios, Vite.
- **Загрузка файлов:** изображения товаров хранятся в каталоге `media/`.

## Структура проекта

```text
config/       настройки Django, URL-маршруты, ASGI и WebSocket-маршрутизация
shop/         каталог, категории, бренды, фотографии, заказы и уведомления
users/        пользователи, роли, регистрация, профили и JWT
frontend/     Vue-приложение, страницы и конфигурация Vite
media/        загруженные изображения товаров
manage.py     команды управления Django
db.sqlite3    локальная база SQLite
```

Дополнительные важные файлы:

- `config/settings.py` — подключённые Django-приложения, SQLite, JWT, CORS, медиа и channel layer.
- `config/urls.py` — HTTP-маршруты, API-роутер и Swagger.
- `config/asgi.py`, `config/routing.py`, `shop/consumers.py` — ASGI и WebSocket-уведомления.
- `shop/models.py`, `shop/serializers.py`, `shop/views.py` — модели магазина, преобразование данных и API.
- `users/models.py`, `users/serializers.py`, `users/views.py` — пользовательская модель и операции с аккаунтами.
- `frontend/src/views/` — страницы интерфейса; `frontend/src/api.js` — общий Axios-клиент с JWT.
- `frontend/vite.config.js` — локальный сервер и прокси к backend.
- `*/migrations/` — миграции схемы базы данных.
- `frontend/package-lock.json` — зафиксированные версии JavaScript-зависимостей.

В репозитории нет отдельного `requirements.txt`: зависимости Python устанавливаются командой из раздела запуска. Не устанавливайте глобальные Python-пакеты, используйте виртуальное окружение.

Основные страницы интерфейса: `/login`, `/catalog`, `/orders`, `/categories`, `/brands`, `/products`, `/users`. Управление товарами, категориями и брендами доступно менеджерам и администраторам; список пользователей — только администраторам. Остальные страницы требуют входа.

### Роли

| Роль | Возможности |
| --- | --- |
| `user` | Каталог, просмотр товаров и оформление заказов; просмотр и отмена собственных заказов; просмотр и изменение своего профиля. |
| `manager` | Возможности пользователя, создание и изменение товаров, категорий, брендов и изображений; получение общих уведомлений о новых заказах. |
| `admin` | Возможности менеджера, просмотр всех заказов и управление пользователями и их ролями. |

Регистрация через API всегда создаёт пользователя с ролью `user`; пароль должен содержать не менее 8 символов. Команда `createsuperuser` создаёт Django-суперпользователя, но прикладная роль `role` по умолчанию остаётся `user`. Чтобы получить административные возможности в интерфейсе магазина и API, после создания суперпользователя войдите в `/admin/` и измените его роль на `admin`. Менеджера можно назначить там же или через API администратора.

Покупатель при создании заказа указывает ID товаров и количество. Сервер берёт актуальную цену из каталога, сохраняет её в позиции заказа и рассчитывает итог. Статусы заказа: `new`, `processing`, `completed`, `cancelled`. Заказ нельзя отменить после завершения или повторно отменить.

## Требования

- Python 3.12 или новее.
- Node.js, совместимый с Vite 7 (Node.js 20.19+ или 22.12+).
- npm.

## Запуск локально в Windows PowerShell

Откройте PowerShell в корне проекта. Backend и frontend запускаются в отдельных терминалах.

### 1. Backend

Создайте и активируйте виртуальное окружение (если `.venv` ещё не создано):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Установите серверные зависимости:

```powershell
python -m pip install Django==6.0.2 djangorestframework==3.16.1 djangorestframework-simplejwt==5.5.1 channels==4.3.2 daphne==4.2.1 django-cors-headers==4.9.0 django-filter==25.2 drf-spectacular==0.29.0 Pillow==12.1.0
```

Подготовьте базу данных и при необходимости создайте администратора:

```powershell
python manage.py migrate
python manage.py createsuperuser
```

Запустите ASGI-сервер (он обслуживает HTTP API и WebSocket):

```powershell
daphne -b 127.0.0.1 -p 8000 config.asgi:application
```

Если команда `daphne` не найдена, проверьте, что виртуальное окружение активировано, либо запустите `python -m daphne -b 127.0.0.1 -p 8000 config.asgi:application`.

### 2. Frontend

В новом терминале из корня проекта выполните:

```powershell
cd frontend
npm install
npm run dev
```

Откройте адрес, напечатанный Vite (по умолчанию http://127.0.0.1:5173). Vite перенаправляет запросы `/api`, `/media` и `/ws` на backend по адресу `127.0.0.1:8000`.

Для production-сборки из каталога `frontend/` используйте `npm run build`; предварительный просмотр сборки запускается командой `npm run preview`.

## Основные адреса

| Адрес | Назначение |
| --- | --- |
| `/api/users/register/` | Регистрация покупателя |
| `/api/users/token/` | Получение пары JWT-токенов |
| `/api/users/token/refresh/` | Обновление access-токена |
| `/api/users/profile/` | Просмотр и редактирование своего профиля |
| `/api/categories/`, `/api/brands/`, `/api/products/`, `/api/images/` | Категории, бренды, товары и изображения |
| `/api/orders/` | Просмотр своих заказов и создание заказа |
| `/api/orders/<id>/cancel/` | Отмена заказа |
| `/api/schema/` | OpenAPI-схема |
| `/api/docs/` | Swagger UI |
| `/admin/` | Панель Django Admin |
| `/ws/orders/` | WebSocket-уведомления о новых заказах |

Пути API имеют завершающий `/`. Маршруты каталога — стандартные CRUD-маршруты Django REST Framework: `GET` списка и объекта, `POST` создания, `PUT`/`PATCH` изменения и `DELETE` удаления. Для заказов доступны `GET /api/orders/`, `GET /api/orders/<id>/`, `POST /api/orders/` и `POST /api/orders/<id>/cancel/`; обычное изменение и удаление заказа не предоставляются. Для `/api/users/profile/` доступны `GET`, `PUT` и `PATCH`; список пользователей и управление ими доступны только администратору.

Создать товар или заказ можно только после создания связанных объектов (категории и бренда для товара) и получения JWT. Каталог, категории, бренды и изображения требуют авторизации для всех операций, включая чтение. В ответах списков применяется пагинация по 10 элементов; проверяйте `next` и `previous`, чтобы получить остальные страницы.

API, кроме регистрации и получения токена, использует JWT в заголовке `Authorization: Bearer <access-токен>`. Для создания заказа передаётся список позиций, например:

```json
{
  "items": [
    { "product_id": 1, "quantity": 2 },
    { "product_id": 3, "quantity": 1 }
  ]
}
```

Поиск товаров выполняется через параметр `search`, например `GET /api/products/?search=телефон`. Список API-ресурсов постраничный (по 10 записей на страницу).

## Данные и настройки

По умолчанию проект использует SQLite (`db.sqlite3`), а загруженные фотографии сохраняет в `media/`. Команда `migrate` создаёт структуру базы. Для входа администратора создайте учётную запись командой `createsuperuser`. Новые покупатели регистрируются запросом к API `/api/users/register/`; экран входа в интерфейсе принимает уже созданные учётные записи.

Текущие настройки Django предназначены для локальной разработки: `DEBUG` включён, ключ `SECRET_KEY` задан в конфигурации, а `ALLOWED_HOSTS` пуст. Перед публикацией проекта настройте секреты и разрешённые хосты через безопасную конфигурацию окружения и отключите режим отладки.

Команда `migrate` сохраняет существующую базу и применяет только новые миграции. Для полностью пустой учебной базы остановите сервер, удалите локальный `db.sqlite3`, затем выполните `python manage.py migrate` и `python manage.py createsuperuser`. Удаление базы необратимо удалит локальные аккаунты, товары и заказы; загруженные файлы находятся отдельно в `media/`.

## Типовой сценарий первого входа

1. Запустите backend и frontend в двух терминалах.
2. Откройте `/admin/` и войдите под аккаунтом, созданным через `createsuperuser`.
3. Создайте хотя бы одну категорию и бренд, затем товар. Изображения можно добавить через раздел товаров или Django Admin.
4. Создайте покупателя через `POST /api/users/register/`, затем войдите в каталог. Форма регистрации в интерфейсе не реализована.
5. Добавьте товары в заказ и просмотрите его на странице `/orders`.

Для регистрации отправьте JSON с `username`, `password` и при необходимости `email` на `POST /api/users/register/`. Пароль должен быть не короче 8 символов. Роль передавать не нужно: новые аккаунты всегда получают `user`.

## Частые проблемы

- **`py` не найден:** установите Python и включите Python Launcher либо используйте `python -m venv .venv` для создания окружения.
- **Ошибка активации PowerShell:** разрешите запуск локального скрипта для текущего пользователя (`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`) либо запускайте интерпретатор напрямую: `\.venv\Scripts\python.exe -m pip ...`.
- **`No module named ...` или `daphne` не найден:** активируйте `.venv` в том же терминале и повторите установку зависимостей.
- **Ошибка подключения в интерфейсе:** убедитесь, что Daphne работает на `127.0.0.1:8000`, Vite — на `127.0.0.1:5173`, и адреса не заняты другими приложениями.
- **Изображение не отображается:** файл должен существовать в `media/`; Django отдаёт медиафайлы в режиме разработки, а Vite перенаправляет `/media` на backend.
- **Вход не работает:** сначала выполните миграции и создайте пользователя; обычный новый пользователь не получает роль администратора.
- **Swagger сообщает 401:** для защищённых операций получите access-токен через `/api/users/token/` и добавьте его как `Bearer <токен>`.

## Примечания

- В backend используется встроенный in-memory channel layer: уведомления предназначены для одного запущенного процесса и пропадают при его перезапуске.
- WebSocket `/ws/orders/` в текущей реализации не проверяет JWT или роль подключившегося клиента. Используйте его только в локальной учебной среде; для публичного развёртывания нужно добавить проверку доступа и настроить безопасный channel layer.
- Vite в режиме разработки проксирует `/api`, `/media` и WebSocket-маршрут `/ws` на локальный backend.
- `frontend/node_modules/` и Python-виртуальное окружение нужны только локально; для воспроизводимой установки используйте `npm install` и команды установки Python-пакетов выше.
- Автоматические тесты backend расположены в `shop/tests.py` и `users/tests.py`; для их запуска из активированного окружения выполните `python manage.py test`.
